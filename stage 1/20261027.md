# 201027 생성한 파일의 변경이력을 Git으로 관리하고 Github로 PUSH하기

## [1] vscode에서 작업폴더 만들고 파일 작성하기

### 관련 단축키

- rm : 파일 삭제(remove) 

```sh
$ rm README.md
#보통은 단독으로 잘 쓰지 않음, 관습적으로 -rf까지 붙여서 씀
```

- rm -rf : r(recursive) 하위 폴더 모두 삭제, f(force) 확인없이 강제 삭제한다는 뜻으로 폴더 전체 데이터를 삭제하며 복구 불가

```sh
$ rm -rf kant/
#cf) rm -rf . : 현재 디렉터리에 있는 것 모두 삭제
```

---

- echo : 내용 작성하기 ('#head 등 마크다운 문법 추가 가능)
```sh
$ echo "# Markdown Tutorial" > README.md
# '#'뒤에서 뒤에 한칸 띄워줘야 인식 / 마크다운에서 '#' 1개 = html의 h1과 동일
# ctrl + shift + v 키로 markdown preview <-> editor 모드 전환 가능
```


## [2] vscode terminal에서 Git 사용하기

### 1. 터미널 shell을 git bash로 바꾸기

- vscode 에서 ctrl + ` 로 터미널 열기

- 우측 하단 화살표 클릭 > select default profile 선택 > git bash 선택

- 터미널 exit 실행 후 다시 ctrl + ` 하면 하단에 git bash로 터미널 열림

- 하단 반반 아이콘 통해 터미널 2개 띄워서 분할 작업 가능

- ctrl + L : clear 명령 실행 단축키

- ctrl + C : 프로세스 중단 단축키 (cf. Q 등)

### 2. Git 최초 설정하기

#### (1) 이메일, username 설정

- $ git config --global : 광역세팅 *대부분 global 설정 / $ git config --local : 로컬세팅

- $ git config --global user.email "leewisdom247@gmail.com" : 이메일 설정

- $ git config --global user.name "leejihye" : username 설정

- $ git config --global --unset user.email : 잘못 적었을 시, 지우기

- $ git config --list : git 설정 리스트 출력하여 username, useremail 잘 뜨는지 확인

#### (2) Git 초기화(Git 저장소 만들고 변경이력 관리 준비)

> git init 으로 git 저장소(.git)를 만들고 앞으로 변경 이력을 관리할 준비를 하는 것,  
> 즉 새로 펼친 공책에 수정 이력 관리 기능을 설치하는 단계

- $ git init : git 초기화하기, 기본 브랜치는 main이라고 뜨며 이 작업을 하면 .git이 생김

- $ ls -al 로 .git(git 저장소) 생성된 것 확인

``` sh
total 12
drwxr-xr-x 1 jihey 197609 0 10월 27 10:07 ./
drwxr-xr-x 1 jihey 197609 0 10월 27 09:58 ../
drwxr-xr-x 1 jihey 197609 0 10월 27 10:07 .git/
# hidden file은 모두 .으로 시작함
```

- $ cd .git : git 저장소로 이동

- $ ls : git에 대한 commit history 저장 공간 내부 확인
```sh
config  description  HEAD  hooks/  info/  objects/  refs/
# 참고:hooks폴더 안에 다양한 설정을 통해 실수와 문제 방지 가능
```

- $ git status : Git 상태 확인 (현재 작업중인 브랜치, 파일변경 여부, 새 파일 여부,  staging 상태, 커밋 필요 여부, 원격 브랜치와의 관계 등을 알 수 있음)

```sh
$ git status
On branch main
No commits yet
nothing to commit (create/copy files and use "git add" to track)
```

📌 touch(파일 생성)와 mkdir(폴더, 디렉터리 생성) 차이 구분 잘 하기

### 3. Git add로 커밋할 변경사항 staging area에 올리기

📌 반드시 ctrl + S 로 저장을 한 후에 뒤의 과정들을 수행해줘야 함
탭 옆에 o 뜨면 저장이 안된 상태 -> ctrl + s로 저장 => 습관화하기!

- $ git add : working directory에서 staging area로 변경사항이 올라가며 Git이 관리되기 시작

```sh
$ git add README.md

$ git status
On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
        new file:   README.md
```

---
✨ [참고] 파일 상태 구분  
- U(Untracked) : Git이 아직 추적하지 않는 상태, 이력관리 요청 전  
- A(Added) : 변경사항이 Staging area로 added 됨, INDEX(=Staging area) ADDED 의미
- M(modified) : 수정된 파일 상태
---

### 4. Git commit으로 커밋(버전) 추가하기

📌 반드시 ctrl + S 로 저장, Git add를 한 후에 commit 추가

- $ git commit -m "메시지 내용" 으로 커밋 추가

```sh
$ git commit -m "feat: Add README.md"

# -m 이하의 이름으로 커밋 메시지 남기며 저장

# 관습적으로 기능추가시 feat, 문서 내용 관련 작업시 docs 키워드를 넣어 메시지 작성
# 앞에 적힌 키워드만 보고도 이게 무슨 작업인지 쉽게 파악할 수 있도록 도와주는 기능

[main (root-commit) 096bb9f] feat: Add README.md
 1 file changed, 0 insertions(+), 0 deletions(-)
 create mode 100644 README.md

$ git status
On branch main
nothing to commit, working tree clean
# working tree = working dr = repository 의미
```

> 만약 -m을 안붙이고 쓰면 ? message 작성하라고 나옴  
> (1) i 키 누르면 삽입, 끼워넣기, insert > docs: 헤더 내용 추가 라고 작성  
> (2) esc로 나와서 명령 모드 진입 > wq 입력(w는 저장, q는 나오기) > 엔터하고 빠져나오기
> *안되면 wq!로 강제로 나올 수 있음. 저장 안하고 나오려면 q!로 그냥 나오기

- $ git log : Git log 확인 / $ git log --oneline : 커밋 필수정보만 간단히 보기
```sh
$ git log
commit 096bb9f0a2070abc78425c3eed66624b32d7f33a (HEAD -> main)
# 커밋 해시값, head가 메인에 가있는 것 확인
Author: leejihye <leewisdom247@gmail.com> *책임자 확인, 추적
Date:   Tue Oct 27 10:21:02 2026 +0900

    feat: Add README.md

# 내용 길어서 (END) 나오는 상태면 Q(QUIT)로 빠져나오기
```

- 기타 참고사항
  - 좌측 changes 에서 파일 선택해서 수정 내용 확인 가능
  - commit 사용하다가 충돌발생시 index lock 걸릴 수 있음 
  - $ git commit -m "feat: 뷸렛 사용법 추가"에서 만약 "제대로 닫지 않으면 dquote>가 뜨며  다음줄까지 이어서 쓰도록 나옴. => ctrl + c로 중지, 빠져나오기


#### (+) checkout으로 head 이동해서 다른 버전 확인해보기(삭제x)

> 헤드 옮겨서 (뒤로 되돌아가기) git reset, git revert으로 내용 지우지 않고 다른 버전보기 
> 몇 칸 이전으로 갈지 횟수로 이동할 수도 있고, 해시값으로 이동할 수도 있음

- $ git checkout 이동할 커밋의 해시값 : 특정 해시값 커밋으로 이동(해시값 status로 확인)

```sh
$ git checkout 39703a7 # 이동할 커밋의 해시값

# 해당 커밋 변경사항까지만 포함된 상태로 되돌아감
# checkout이라서 뒤의 것이 지워진 것이 아니고 잠깐 점프만 한 상태일 뿐

jihey@LAPTOP-T7TVDFIE UCRT64 C:/Users/jihey/kant ((39703a7...))
# 아랫줄에서 head가 main이 아니고 해당 해시값으로 나타나는 것 확인 가능
# checkout 전에도 파일 저장상태 반드시 잘 확인해야 함

```

- $ git log --oneline : 헤드있는 커밋만 보임

```sh
jihey@LAPTOP-T7TVDFIE UCRT64 C:/Users/jihey/kant ((39703a7...))
$ git log --oneline
39703a7 (HEAD) docs: 헤더 내용 추가
096bb9f feat: Add README.md
```

- $ git log --oneline --all : 전체 커밋 확인 가능

```sh
jihey@LAPTOP-T7TVDFIE UCRT64 C:/Users/jihey/kant ((39703a7...))
$ git log --oneline --all
cbad1a2 (main) feat: 뷸렛 사용법 추가
39703a7 (HEAD) docs: 헤더 내용 추가
096bb9f feat: Add README.md
```

- $ git checkout main : 헤드를 메인으로 이동, 메인 브랜치로 스위칭하여 버전 원복시키기

```sh
$ git checkout main

# head : 내가 현재 어떤 커밋을 기준으로 작업하곡 있는지 나타내는 포인터
# main : 브랜치 이름이자, 해당 브랜치의 최신 커밋을 가리키는 포인터

```

### 5. Github로 커밋 내용을 push(업로드)하여 공유, 협업, 백업

1. Github에서 repository 생성

> 주의! 깃허브에서 자동 번역기능끄고 영문으로 작업하기(오류 방지)

- new repository 생성 : 초록색 NEW 버튼이나 우측 상단 + 눌러서 repository 생성 가능

- repository 초기 설정 : name, description 등 설정
  - choose visibility : public(공개) private(비공개, 승인하는 사람만 접근 가능하도록)
  - add readme : readme.md 파일 자동 생성
  - Add .gitignore : Git이 관리하지 않아도 되는 파일들 등록, 관리
  - add license : license 표기
  - 마지막으로 create repository

- readme 파일 없이 생성한 경우, HTTPS/SSH 설정 후 오른쪽에 뜨는 리포 주소 확인, URL 복사
![alt text](image-2.png)
 
```
# 하단부 코드 참고
echo "# Kant" >> README.md
git init
git add README.md
git commit -m "first commit"
git branch -M main *로컬 브랜치명을 통째로 스위칭(main으로)
git remote add origin https://github.com/jayjay13579/Kant.git
git push -u origin main
```

(+참고) 리포 삭제하기
- 리포 들어가서 settings 메뉴 클릭, 최하단 danger zone에서 delete this repository (이메일 혹은 모바일 이중인증까지 완료해야 삭제)


2. repository와 로컬 작업 파일의 Git 연결하기

- 생성한 repo url 주소 copy(https://github.com/jayjay13579/Kant.git) 후 다시 vscode로 복귀

- $ git remote -v : 연결 상태 확인

```sh
$ git remote -v
# 아무것도 뜨지 않으면 연결 없는 상태(기본)
# remote : 내 컴퓨터(로컬)가 아닌 다른 컴퓨터(깃허브 서버)에 저장되어 있어서 '원격'

```

- $ git remote add (별칭 원주소): push 할때마다 긴 주소를 붙이지 않아도 되도록 별칭 추가하면서 원격 저장소의 주소를 로컬 Git에 등록 

```sh
$ git remote add origin https://github.com/jayjay13579/Kant.git
# origin 이라는 이름으로 뒤의 url 주소를 등록하겠다

# 주소 등록 후 다시 연결 확인
$ git remote -v
origin  https://github.com/jayjay13579/Kant.git (fetch) # 변경사항 없는지 확인
origin  https://github.com/jayjay13579/Kant.git (push)  # Github로 올림

# git remote remove origin 으로 origin 잘못 적은 것 지울 수 있음(??)
```

3. Git push 하기

- push하기 전에 status 깔끔한지, 커밋안한거 없는지 확인

```sh
$ git status
On branch main
nothing to commit, working tree clean
```

- $ git push 주소 브랜치 : push 보낼 주소(github repo의 url), 보낼 브랜치까지 정확히 명시해서 보내기

```sh
$ git push origin main 
# main 브랜치의 커밋을 origin이라는 원격 레포지토리에 보낸다
# 작업 후 이전에 생성했던 리포에 main 커밋의 내용들이 나옴
```
