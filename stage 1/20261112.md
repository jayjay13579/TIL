## 1️⃣ (windows) Docker 사용을 위한 리눅스 환경 설정

### 1. 운영체제, 커널 개념 이해하기

- 운영체제 : 컴퓨터를 사용할 수 있게 해주는 전체 시스템(Windows, macOS, Ubuntu 등)

- 커널 : 운영체제의 핵심 프로그램, CPU·메모리·파일 같은 컴퓨터 자원을 관리 => (ex) linux 커널을 쓰는 것들은 linux 운영체제가 됨!
```text
프로그램: “파일을 읽어줘”
       ↓
커널: 파일을 읽어 프로그램에 전달
       ↓
프로그램: 받은 내용을 보여 줌
```

|운영체제|사용 커널|
|---|---|
|Windows|Windows NT 커널|
|macOS|XNU 커널|
|Ubuntu 등 Linux 운영체제|Linux 커널|

### 2. WSL(Windows Subsystem for Linux)의 필요성

#### - 왜 Windows에서는 Docker 사용을 위해 WSL을 설치할까?
 - Docker는 애초에 linux 커널의 기능(프로그램들을 서로 분리하고 사용할 수 있는 자원을 관리)을  
   쉽게 이용할 수 있도록 하는 도구로 만들어짐
 - 웹 사이트나 앱을 운영하는 서버에서도 linux를 많이 사용, 그래서 개발자가 자기 컴퓨터에서  
   linux 컨테이너를 만들고 시험한 뒤, linux 서버에 올리는 흐름이 흔함
 - 그런데 Windows에는 Linux 커널이 없으므로, Linux 컨테이너를 실행하려면 Linux 커널을 제공할 환경이 필요
 - 따라서 Windows에서도 서버와 비슷한 linux 환경에서 개발하고 싶다!  
   -> 주로 WSL을 통해 Linux 커널 제공받고 linux 컨테이너를 만들어서 개발
 - 따라서 '윈도우에서 리눅스 환경을 사용할 수 있게 해주는 기능'인 WSL을 설치하여  
   리눅스 커널을 제공받고, 리눅스 컨테이너가 실행될 수 있는 환경 만듦
 - 사실 WSL이 없어도 Windows에서 Docker를 쓸 수는 있음.. (linux 컨테이너 실행을 못하게 될 뿐...)

### 3. WSL 설치하기
```sh
# WSL 설치 명령어가 Windows에 이미 준비되어 있음. winget에서 설치X
$ wsl --install
```
- 설치 중 권한 오류가 뜨면 '설정 > 고급 > 개발자 모드 ON, sudo ON'을 설정하고  
  $ sudo wsl --install (sudo를 앞에 추가적으로 적기) 실행
- 설치 후 기능 검색 > windows 기능 켜기/끄기 > hyper-v, 리눅스용 windows 하위 시스템  
  총 2개 항목 체크 후 재부팅

## 2️⃣ Docker 개념과 기본 활용법

### 0. Docker 설치하기
```sh
$ winget install Docker.DockerDesktop
```
- 설치 후 github 계정을 연결하여 Docker 회원가입

### 1. Docker란?

- Docker : 프로그램(앱)과 실행에 필요한 환경을 컨테이너로 만들고 실행/관리할 수 있게 해주는 도구
  - 컨테이너 : 프로그램과 그 실행 환경(운영체제 파일, 패키지, 설정 파일 등)을 담은 독립된 실행 공간
  - 특히, windows에서는 linux 컨테이너들이 WSL가 제공한 linux 커널을 공유하여 사용

- 프로그램과 실행 환경을 컨테이너로 구성하여 공유, 개발 환경과 실행 환경 차이로 인한 오류를 줄임

- 가상머신(vm) vs 컨테이너 차이
  - 각 vm 마다 게스트os를 설치, 즉 os 안에 os를 직접 설치하는 구조 -> 무거움
  - docker 컨테이너는 게스트os 없이(컨테이너마다 별도의 운영체제 커널을 실행X)  
    호스트os 기능(리눅스 커널 등) 그대로 활용, 패키지, 설정, 앱 등만 모듈화하면 됨 

<br>

### 2. image와 container 개념

- images : 닌텐도의 게임 칩같은 개념(칩을 바꿔 끼우면 다른 게임이 실행), 컨테이너 만들기 위한 틀/설계도  
  - 앱을 실행하는 데 필요한 파일 시스템(최소한의 OS 파일, 라이브러리, 실행 파일, 설정) 등 정보 포함
  - 읽기 전용으로 변하지 않음. postgres, ubuntu, mysql 등이 각각 하나의 이미지!
  - 데스크탑 화면 우측 상단 점 9개 아이콘 > docker hub에서 이미지 검색 및 다운 가능  
    *official image, verified publisher 필터 적용하여 신뢰할 수 있는 이미지만 사용하기
  - 같은 이미지를 여러번 실행하면 각각 다른 컨테이너가 만들어짐

- containers : 닌텐도 칩(images)가 실행된 상태, 칩 꽂고 기기를 끌 수 있는 것처럼 컨테이너도 Off 가능
  - 이미지를 실행한 것(실행 인스턴스), 이미지 위에 쓰기 가능한 레이어 덧붙이고 격리된 프로세스로 실행

=> 즉, 이미지는 컨테이너를 만들기 위한 설계도, 컨테이너는 그 설계도로 만든 실행 공간

<br>

### 3. 사용 전 Docker 설치 상태 등 확인

- $ docker --version : 설치 여부와 버전 확인

- $ docker compose version : Docker Compose가 설치되어 있는지와 버전을 확인
  - Docker Compose는 여러 컨테이너를 함께 실행/관리하는 도구
  - (ex) 웹 사이트를 만들때 웹 서버, 데이터베이스 같이 실행해야 한다면, compose로 둘을 한꺼번에 관리

- $ docker info : Docker가 실행 중인 환경의 상세 정보
  - 실행 중인 컨테이너 수, 이미지 수, Docker 엔진 버전 등을 확인
  - Docker 엔진에 연결할 수 있는지 확인할 때도 유용

### 4. 이미지, 컨테이너 관련 기본 작업 (CLI)

- 이미지 받기 : $ docker pull + 이미지 이름 (+ 필요시 :태그를 통해 받아올 특정 버전 명시 가능)  
  (ex) python(태그를 쓰지 않으면 최신버전 설치) / python:3.12 처럼 태그를 쓰면 3.12버전 설치
```sh
$ docker pull hello-world
Using default tag: latest
latest: Pulling from library/hello-world
Digest: sha256:cf1b20a0c89a666b6950fecda7ccbc1b1a86520e7c53f908f3a21e79d0d60458
Status: Downloaded newer image for hello-world:latest
docker.io/library/hello-world:latest
```

- 이미지 목록 확인 : $ docker image ls (혹은 docker images)
```sh
$ docker image ls # $ docker images 와 동일
IMAGE                ID             DISK USAGE   CONTENT SIZE   EXTRA
hello-world:latest   c567b231f656       25.9kB         9.49kB    U # in use 의미
```

- 컨테이너 실행(이미지가 컨테이너 생성 후 실행) : $ docker run + 이미지 이름 / ID
  - 단, 기존에 없는 이미지를 바로 run 돌리면, 자동으로 pull 받은 후 실행함
  - 보통 --name으로 컨테이너에 이름을 붙이며, 이미지별로 실행 옵션이 살짝씩 달라짐(-it 등)!
```sh
$ docker run hello-world
Unable to find image 'hello-world:latest' locally # 로컬에 없지만
latest: Pulling from library/hello-world # 자동으로 받아와서 실행
Digest: sha256:cf1b20a0c89a666b6950fecda7ccbc1b1a86520e7c53f908f3a21e79d0d60458
Status: Downloaded newer image for hello-world:latest
```

- 이미지 삭제 : $ docker rmi + 이미지 이름 / ID
  - 단, 이미지 삭제한다고 그 이미지를 쓰는 컨테이너까지 자동으로 삭제되진 않음
  - 오히려 컨테이너가 남아 있으면 이미지 삭제가 거부될 수 있어서 보통 **컨테이너를 먼저 삭제!**
```sh
$ docker rmi hello-world
Untagged: hello-world:latest
Deleted: sha256:cf1b20a0c89a666b6950fecda7ccbc1b1a86520e7c53f908f3a21e79d0d60458
```

- 컨테이너 목록 확인 : $ docker ps -a (실행중 컨테이너만 확인하려면 docker ps까지만)
```sh
$ docker ps -a
CONTAINER ID   IMAGE         COMMAND    CREATED              STATUS                          PORTS     NAMES
2b414f3066d8   hello-world   "/hello"   About a minute ago   Exited (0) About a minute ago             goofy_goldstine
```

- 컨테이너 중지 : $ docker stop + 컨테이너 이름 / ID
```sh
$ docker stop 5915e4d6e32e
5915e4d6e32e
```

- 중지된 컨테이너 다시 실행 : $ docker start + 컨테이너 이름 / ID
```sh
$ docker start 5915e4d6e32e
```

- 컨테이너 삭제 : $ docker rm + 컨테이너 이름 / ID(-f 붙이면 실행 컨테이너도 강제 삭제)
```sh
$ docker rm 1b089e64d0f1
1b089e64d0f1
```

### 1. Ubuntu (+셸에 들어가 명령어 써 보고, 컨테이너 다뤄 보기)

- ubuntu 받아오기
```sh
$ docker pull ubuntu:24.04
```

- 컨테이너 실행
  - ubuntu 실행 옵션 : -it(interactive, terminal) - 터미널로 실행 / bash - 컨테이너 시작시 bash 실행
  - -it 없이 실행하면 bash가 입력을 받지 못해 곧바로 종료됨!
```sh
$ docker run -it --name my-server ubuntu:24.04 bash # 
# 대화형 터미널로 실행, 컨테이너 name은 my-server
# ubuntu:24.04 이미지로 컨테이너 생성, bash shell 지정
```

- 컨테이너 내부에서 작업
```sh
# 현재 사용자 이름 확인
root@cc71a286e620:/# whoami
root # 현재 컨테이너 안에서 관리자 사용자로 작업 중

# 현재 위치(/)에 있는 파일과 폴더 목록 확인
root@cc71a286e620:/# ls
bin dev home (중략)

# ubuntu에서 설치 가능한 프로그램들의 '목록과 버전 정보' 갱신
# 프로그램 자체를 설치하거나 업데이트하지는 않음
root@cc71a286e620:/# apt update

# etc(시스템과 프로그램 설정파일이 있는 곳)으로 이동
root@cc71a286e620:/# cd etc 

# os-release 파일 확인(ubuntu 버전 등 컨테이너 운영체제 환경정보)
# 도커 데스크탑 > my-server 컨테이너 > Exec > 터미널과 똑같이 os-release 내용 확인 가능
root@cc71a286e620:/etc# cat os-release
PRETTY_NAME="Ubuntu 24.04.5 LTS"
NAME="Ubuntu"
VERSION_ID="24.04"

# 셸에서 exit하면 컨테이너도 종료(중지)

# 중지된 컨테이너 다시 실행, 재시작할때도 셸에 연결하기 위해 -ai 옵션 추가
$ docker start -ai my-server
# a: attach, 컨테이너 출력에 연결 / i: interactive, 명령어 입력할 수 있도록 연결
# 파일 작성 등 컨테이너 변경하려면 앞서 실행을 해야해서!

# 컨테이너 내에서 파일 생성+작성 : echo 사용
root@cc71a286e620:/# echo "# Hello Docker!" > README.md
```

### 2. Nginx (+웹 서버 활용)

#### (1) Nginx 활용 기초

- nginx 받아오기
```sh
$ docker pull nginx
```

- 특정 포트 사용중인 프로그램 목록 확인
```sh
$ netstat -ano | grep :8080  # 띄어쓰기 다 맞아야함 주의! (mac: lsof -i:8080)
# netstat -ano는 네트워크 연결과 포트 사용 정보, 프로세스 ID를 보여 주고,
# grep :8080은 그중 :8080이 포함된 줄만 골라 보여 줌
  TCP    0.0.0.0:8080  #8080확인    0.0.0.0:0              LISTENING       24120
  TCP    127.0.0.1:8080         0.0.0.0:0              LISTENING       22556
  TCP    [::]:8080              [::]:0                 LISTENING       24120
  TCP    [::1]:8080             [::]:0                 LISTENING       22556
```

<details> <summary> 포트 개념 </summary>
- 포트 : 컴퓨터에서 특정 프로그램으로 연결하기 위한 논리적인 번호
(브라우저에서 localhost:8080 접속>내 컴퓨터의 8080번 포트>컨테이너의 80번 포트>Nginx 웹 서버가 응답)

- p 8080:80은 **“내 컴퓨터의 8080번으로 요청이 오면, Nginx가 기다리는 컨테이너의 80번으로 전달해 줘”*
  - p 8080:80
     │   └─ Nginx가 컨테이너 안에서 기다리는 포트
     └──── 내 컴퓨터에서 접속할 포트
  - Nginx도 처음 실행하면 **“80번 포트에서 웹 요청을 기다린다”**고 미리 정해져 있음!  
   그래서 Nginx에게 요청을 보내려면 컨테이너 안의 80번으로 보내야 함

- 포트 번호는 0부터 65535까지. 그중 웹 서버에서 사용할 번호를 고를 수 있지만, 아무 번호나 막 쓸 순 X
- 0~1023번은 잘 알려진 서비스에 자주 쓰이는 번호, 사용 환경에 따라 특별한 권한이 필요할 수 있음
- 그래서 연습할 때는 보통 8080, 3000, 8000처럼 1024 이상의 번호를 많이 사용
- 이미 다른 프로그램이 사용 중인 포트를 지정하면 이미 사용 중이라는 오류 -> 다른 번호로 변경 지정  
  (다만 실패한 컨테이너가 my-webserver라는 이름으로 이미 만들어져 남아 있을 수 있음.  
   그 경우에는 먼저 docker ps -a로 확인하고, 남아 있다면 삭제한 뒤 다시 다른 포트번호 지정하여 실행)
</details>

- nginx 이미지로 웹 서버 컨테이너 실행하기
  - 바깥(내 PC) 포트 번호는 빈 번호 중에 내가 고름, 안쪽(컨테이너) 포트번호는 nginx이 정해둔 값 사용
```sh
# 실행 옵션 : d(dettach) - 백그라운드 실행, p(port) - 포트(외부:내부) 지정
$ docker run -d --name my-webserver -p 8080:80 nginx
# 현재 터미널 꺼지지 않도록 백에서 실행, 컨테이너 name은 my-webserver,
# 내 컴퓨터의 8080번 (외부)포트로 온 요청을 nginx가 기다리는 컨테이너의 80번 (내부)포트로 전달
# 브라우저에서는 localhost:8080에 접속하면 내 컴퓨터의 Nginx가 보내 준 페이지를 볼 수 있음
```

- 주소로 요청 보내고 서버 응답 내용(웹 페이지 내용) 확인
  - nginx에서의 curl + url : nginx가 웹페이지의 html을 응답, 페이지 내용(html) 확인 가능
```sh
$ curl http://localhost:8080
$ curl localhost:8080 # 프로토콜 생략 가능
# 웹 브라우저에서 localhost:8080 여는 것과 동일

(중략)
<body>
<h1>Welcome to nginx!</h1> # localhost:8080의 html 내용 출력
(중략)
```

- 실행중 컨테이너(nginx 컨테이너) 안으로 들어가 작업
```sh
$ docker exec -it my-webserver bash # exec : excecute
```

#### (2) 컨테이너 내부에서 페이지 내용 수정
- 기본 웹페이지 파일(index.html)이 있는 폴더(html)로 이동
```sh
root@47adfabb1cf3:/# cd usr/share/nginx/html
```

- 웹페이지 파일 현재 내용을 터미널에서 확인하기
```sh
root@47adfabb1cf3:/usr/share/nginx/html# cat index.html #웹 브라우저 내용 html을 볼 수 있음
```

- 내용 수정하기(echo 활용)
```sh
root@47adfabb1cf3:/usr/share/nginx/html# echo '<h1>Hello Docker!!!</h1>' > index.html
# 문자열을 작은따옴표로 감싸면 느낌표 포함 가능, '>' 하나면 overwriting

root@47adfabb1cf3:/usr/share/nginx/html# cat index.html # 파일 내용 다시 확인하면
<h1>Hello Docker!!!</h1> # echo 이후의 내용으로 덮어쓰기 된 것 보임
```

#### (3) 웹서버 구동상태 모니터링(로그 확인)

```sh
$ docker logs my-webserver
```

```sh
$ docker logs -f my-webserver # f:follow, 추적
```

### 3. MySQL (+환경 변수로 DB 서버 띄우기)

#### (1) MySQL 활용 기초
- mysql 받아오기
```sh
$ docker pull mysql:8.4 # 태그 붙여서 8.4 버전 받아옴
```

- 필수 환경변수 전달하며 컨테이너 실행
  - MySQL의 필수 환경변수 : MYSQL_ROOT_PASSWORD=비밀번호
    - MySQL 이미지 처음 실행해서 새 데이터 베이스 만들 때는 ROOT 비밀번호 필수 지정!
    - 이게 빠지면 MySQL이 초기화를 거부하고 종료, 컨테이너는 만들어졌을 수 있지만, MySQL 서버는 미실행
  - 기타 실행 옵션 : e - 컨테이너에 설정값을 전달, p - 포트
```sh
$ docker run -d --name my-sql -e MYSQL_ROOT_PASSWORD=admin1234 -p 3306:3306 mysql:8.4
```

- 로그 확인, 접속 가능 여부 확인
```SH
$ docker logs -f my-sql
# 마지막 줄 ready for connections 메시지 확인
# 메시지가 뜨면 MySQL이 초기 설정 마치고 접속받을 준비 완료된 상태
```

#### (2) 컨테이너 내부에서 데이터베이스 생성

- 컨테이너 내부로 들어가기 
  - 옵션 : u+유저명(바로 붙여 적음), p - 패스워드 입력
```sh
$ docker exec -it my-sql mysql -uroot -p
# 터미널 입력 연결, my-sql(컨테이너 이름)에서 mysql 프로그램에 접속하여
# root 사용자로 접속할 것, 단, 비밀번호를 입력받겠다!
```

- 기존에 설정한 비밀번호 입력하기(눈에 보이지 X)
  - [참고] ctrl + u 로 보이지 않는 패스워드 초기화가능

- mysql 내부에서 데이터베이스 목록 확인하기
  - SQL문은 관례대로 대문자로 작성하고 끝에 세미콜론 ; 붙임
```sh
mysql> SHOW DATABASES;  # BASES 복수형 주의

+--------------------+
| Database           |
+--------------------+
| information_schema |
| mysql              |
| performance_schema |
| sys                |
+--------------------+
4 rows in set (0.01 sec)
```

- 데이터베이스 생성하기
```sh
mysql> CREATE DATABASE shop; # shop이라는 이름의 DB 생성

Query OK, 1 row affected (0.01 sec)
mysql> SHOW DATABASES;
+--------------------+
| Database           |
+--------------------+
| information_schema |
| mysql              |
| performance_schema |
| shop               |
| sys                |
+--------------------+
5 rows in set (0.00 sec)
```
🚨 주의 : my sql 실행 컨테이너 자체를 삭제하면? 당연히 컨테이너에서 만들었던 shop database도 사라짐
          이렇게 데이터까지 날라가지 않도록 하려면? -> volume개념(물리 공간을 sql과 연결)을 활용

### 4. PostgreSQL 

- Postgres 받아오기
```sh
$ docker pull postgres:18 # 태그붙여 18버전 받아옴
```

- 필수 환경변수 전달하며 컨테이너 실행
  - Postgres의 필수 환경변수 : POSTGRES_PASSWORD=비밀번호 (최초 지정) + 포트 최초지정
```sh
$ docker run -d --name my-pg -e POSTGRES_PASSWORD=admin1234 -p 5432:5432 postgres:18
# 백그라운드에서 my-pg라는 이름의 컨테이너를 다음 비밀번호와 포트를 지정하여 실행
```

- 로그 확인, 접속 가능 여부 확인
```SH
$ docker logs my-pg
# 마지막 줄 ready for connections 메시지 확인
```

- 컨테이너 내부로 들어가기
```sh
$ docker exec -it my-pg psql -U postgres
# 터미널 입력 가능하도록, my-pg 컨테이너를 열어 명령어를 실행,
# psql(postgreSQL) 프로그램을 실행하고 postgres라는 기본 User(U)사용자로 접속
```

- 컨테이너 내에서 DB 목록 조회하기
```SH
postgres=# \l  # 역슬래시 소문자 L 로 list 조회
```
