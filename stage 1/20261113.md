# 00 [Docker] 명령어 복습 및 자료보충

## 1. run(컨테이너 생성 및 실행), exec(실행 중 컨테이너 안에서 명령 실행) 명령어 모양 확인

*()는 생략 가능, 나머지는 필수 작성

|이름 앞(Docker가 해석하는 옵션)|이름 뒤(컨테이너 안에서 실행할 프로그램, 그 프로그램 옵션)|
|---|---|
|docker  **run**   (Docker 옵션) **이미지명**   |  (컨테이너에서 실행할 명령) (그 명령의 옵션)|
|docker **exec** (Docker 옵션) **컨테이너명** | **컨테이너에서 실행할 명령**   (그 명령의 옵션)|

### (1) docker run ~ 명령어와 옵션

```sh
# docker  run (Docker 옵션)                                                   이미지명 ㅣ    (컨테이너에서 실행할 명령)  (그 명령의 옵션)
docker run   -it --name my-server                                           ubuntu:24.04    bash 
docker run   -d --name my-webserver -p 8080:80                              nginx
docker run   -d --name my-sql -e MYSQL_ROOT_PASSWORD=admin1234 -p 3306:3306 mysql:8.4
docker run   -d --name my-pg -e POSTGRES_PASSWORD=admin1234 -p 5432:5432    postgres:18
```
- docker run에서 자주 쓰는 옵션

| 옵션 | 의미 | 예시 |
|---|---|---|
| `--name` | 컨테이너 이름 지정 | `--name my-webserver` |
| `-d`, `--detach` | 백그라운드 실행 | `-d` |
| `-i`, `--interactive` | 표준 입력을 열어 둠 | `-i` |
| `-t`, `--tty` | 터미널 화면 할당 | `-t` |
| `-p`, `--publish` | 호스트와 컨테이너의 포트 연결 | `-p 8080:80` |
| `-e`, `--env` | 환경변수 전달 | `-e POSTGRES_PASSWORD=...` |
| `--env-file` | 파일에서 환경변수 읽기 | `--env-file ./app.env` |
| `-v`, `--volume` | 볼륨 또는 호스트 폴더 연결 | `-v pgdata:/var/lib/postgresql` |
| `--mount` | 저장 공간을 명시적인 형식으로 연결 | `--mount type=volume,src=pgdata,dst=/var/lib/postgresql` |
| `--rm` | 컨테이너 종료 시 자동 삭제 | `--rm` |
| `-w`, `--workdir` | 컨테이너 내부 작업 폴더 지정 | `-w /app` |
| `-u`, `--user` | 컨테이너에서 실행할 사용자 지정 | `-u 1000:1000` |
| `--network` | 연결할 Docker 네트워크 지정 | `--network my-network` |
| `--restart` | 자동 재시작 정책 설정 | `--restart unless-stopped` |
| `--memory` | 메모리 사용량 제한 | `--memory 512m` |
| `--cpus` | CPU 사용량 제한 | `--cpus 1.5` |
| `--entrypoint` | 이미지의 기본 진입 프로그램 변경 | `--entrypoint sh` |

### (2) docker exec ~ 명령어와 옵션

```sh
# docker exec (Docker 옵션) 컨테이너명 | 컨테이너 내 명령(PG)  (그 명령의 옵션)
docker exec  -it           my-webserver    bash 
docker exec  -it           my-sql          mysql               -uroot -p
docker exec  -it           my-pg           psql                -U postgres
```

- docker exec에서 자주 쓰는 옵션

| 옵션 | 의미 | 예시 |
|---|---|---|
| `-i`, `--interactive` | 입력을 열어 둠 | `-i` |
| `-t`, `--tty` | 가상 터미널 할당 | `-t` |
| `-d`, `--detach` | 실행할 명령을 백그라운드로 실행 | `-d` |
| `-e`, `--env` | 이번에 실행할 명령에 환경변수 전달 | `-e MODE=test` |
| `-u`, `--user` | 이번 명령을 실행할 사용자 지정 | `-u root` |
| `--env-file` | 파일에서 이번 명령의 환경변수 읽기 | `--env-file ./app.env` |
| `-w`, `--workdir` | 이번 명령의 작업 폴더 지정 | `-w /app` |
| `--privileged` | 이번 명령에 확장된 권한 부여 | 특별한 경우에만 사용 |
| `--detach-keys` | 터미널 연결을 분리하는 키 지정 | 필요할 때 사용 |

# 01 [Docker] 파일 import, 볼륨 연결

## 1️⃣ Docker 컨테이너에 DB import하기 (복사, 입력 2가지 방법)

> 실제 현업에서는 터미널에서 직접 테이블 만들지 않고 별도 sql 파일 만들어서 컨테이너에 push
> 프로젝트의 sql 파일 생성한 후, (1)컨테이너 내부에 복사, 혹은, (2)복사없이 로컬에서 바로 전달

### 사전작업 : SQL 파일 만들기

- 프로젝트 내 DB파일(.sql 확장자) 생성
```sh
touch kant_shop.sql 
```

- SQL 파일 작성
  - 테이블 내용은 소괄호() 안에 적고 콤마,로 구분
  - 각 줄 마지막에 세미콜론 ; 입력 필수
  - SQL문 주석은 --로 처리
```sql
-- 0. 이미 데이터베이스가 있다면 삭제하고 계속 실행
DROP DATABASE IF EXISTS kant_shop;

-- 1. 데이터베이스 생성
CREATE DATABASE kant_shop;

-- 2. 데이터베이스에 접속(c:connect), 특정 DB 사용하겠다는 뜻
\c kant_shop

-- 3. 상품 테이블 생성 (필드+데이터타입+null여부 등 작성)
CREATE TABLE product
(
    id SERIAL PRIMARY KEY, --SERIAL: 번호 자동 증가, PRIMARY KEY 고유키
    name VARCHAR(100) NOT NULL, --VARCHAR(variable character): 최대 100자
    price INT NOT NULL, --NOT NULL : 빈값 불가
    stock INT NOT NULL   
);

-- 4. 초기 데이터 입력(테이블에 추가)
INSERT INTO product (name, price, stock) VALUES -- 저장할 대상 되는 컬럼들 입력
('무선 키보드', 35000, 120),
('게이밍 마우스', 28000, 85),
('27인치 모니터', 259000, 15),
('USB-C 허브', 19900, 200),
('노트북 거치대', 24000, 7); --마지막 데이터에만 ; 붙이기
```
<br>

### 방법 1. 외부 SQL 파일을 Docker 컨테이너로 복사(copy)

- 외부 SQL 파일을 컨테이너 내부로 copy
  - docker cp + 대상 파일 + 복사 받을 컨테이너/내부 저장 경로/복사본 이름(지정)
  - 맨 뒤에 폴더 경로까지만 적고 끝내면 원래 파일명이 그대로 복사됨!
```sh
# kant_shop.sql 파일을 my-pg 컨테이너 tmp 폴더로 kant_shop.sql 이름으로 저장
docker cp kant_shop.sql my-pg:/tmp/kant_shop.sql  # cp = copy

# 처리 결과 확인
Successfully copied 1.06kB (transferred 3.07kB) to my-pg:/tmp/kant_shop.sql
```

- 컨테이너 안의 복사본을 psql로 읽어오기
```sh
docker exec -it my-pg psql -U postgres -f /tmp/kant_shop.sql
# -f 는 파일

# 결과 확인
CREATE DATABASE
You are now connected to database "kant_shop" as user "postgres".
CREATE TABLE
INSERT 0 5
```

- 데이터 조회
```sh
docker exec -it my-pg psql -U postgres -d kant_shop
kant_shop=# SELECT * FROM product;
# product 테이블의 모든 칼럼(*) 데이터 보여줌

# 결과 확인
 id |     name      | price  | stock 
----+---------------+--------+-------
  1 | 무선 키보드   |  35000 |   120
  2 | 게이밍 마우스 |  28000 |    85
  3 | 27인치 모니터 | 259000 |    15
  4 | USB-C 허브    |  19900 |   200
  5 | 노트북 거치대 |  24000 |     7
(5 rows)
```
<br>

### 방법 2. 외부 SQL 파일의 '내용'을 Docker 컨테이너에 입력
> 파일 복사해서 컨테이너에 담지 X, 바로 로컬에서 컨테이너 내부로 파일 전달하고 psql로 실행!

- 로컬 파일 내용을 컨테이너 내부 명령에 입력 (파일에 든 SQL문을 읽고 실행하게 함)
  - 파일을 입력으로 전달할 때는 가상 터미널 옵션 -t를 붙이지 않음!
```sh
# my-pg 컨테이너로 명령 실행 + 옵션 < 입력할 로컬 파일 경로
# 참고로 '<'은 shell의 문법
docker exec -i my-pg psql -U postgres < kant_shop.sql # t 빼야 함!

# 결과 확인
CREATE DATABASE
You are now connected to database "kant_shop" as user "postgres".
CREATE TABLE
INSERT 0 5
```

- 테이블 목록 및 데이터 조회
  - -d + 데이터베이스 이름 옵션으로 데이터베이스 지정하여 접속(exec)하기
  - 컨테이너 내부에서 \dt(discribe tables) 입력하여 테이블 목록 확인
```SH
docker exec -it my-pg psql -U postgres -d kant_shop # 
kant_shop=# \dt  # 현재 접속한 데이터베이스의 테이블 목록 보임
           List of tables
 Schema |  Name   | Type  |  Owner   
--------+---------+-------+----------
 public | product | table | postgres
(1 row)

kant_shop=# SELECT name, price FROM product; # 으로 데이터 조회
# product 테이블의 name, price 칼럼 데이터 보여줌
```

# 02 [Docker] Docker Compose

## 1️⃣ docker compose 개념

### 1. compose의 필요성

- 문제 : 컨테이너 실행 명령을 매번, 컨테이너마다 다르게 직접 입력하기 힘듦
```sh
docker run -d --name my-pg \
-e POSTGRES_PASSWORD=admin1234 \
-p 5432:5432 postgres:18
# [참고] docker에서 \(역슬래시)로 줄바꿈하며 코드 적을 수 있음
```
- 해결 : docker compose 활용하면 복잡한 입력없이 docker run 명령 처리 가능!
  - compose가 실행 옵션들을 compose.yaml 파일에 선언해 둠

|docker run 옵션|compose.yaml 키|
|---|---|
|--name my-pg|container_name: my-pg|
|postgres:18|image: postgres:18|
|-e POSTGRES_PASSWORD=1234|environment:|
|-p 5432:5432|ports:|
|-v pgdata:/var/lib/postgresql|volumes:|

=> 같은 설정을 compose.yaml 파일에 모아 적기!
```sh
services: # 서비스 이름, compose에서 이 설정 전체를 부르는 이름(다음 줄에 적음!)
  my-pg:  # 서비스 이름을 my-pg로 지정
    image: postgres:18 # postgres 이미지를 사용
    environment: # 환경변수
      POSTGRES_PASSWORD: admin1234 #비밀번호
    ports: #포트번호
      - "5432:5432" # "외부:내부"
```

<br>

### 2. compose.yaml 파일

- Docker compose는 (기본적으로 현재 폴더에서) compose.yaml을 읽고 그 설정에 따라 컨테이너 실행

- 프로젝트 폴더 내 compose.yaml 파일을 생성, compose 항목을 yaml 규칙에 따라 작성
  - compose 항목 : services(서비스 이름), image(사용 이미지), environment(환경변수), volumes(볼륨이름) 등
  - YAML 문법 : 데이터를 적는 형식 중 하나, 이 규칙으로 작성한 파일의 확장자명(.yaml)이기도 함
    - 들여쓰기로 항목 포함관계 표시 (들여쓰기는 스페이스 2칸, 탭 사용 금지!)
    - '-'로 목록의 항목 표시
    - 키: 값 구조로 콜론(:) 뒤에는 반드시 공백 한 칸

- 한 compose.yaml 내에 여러 서비스가 같이 적힐 수도 있고, 그냥 yaml 파일들을 다 따로 만들 수도 있음 
  - 한 파일에 여러 서비스: 한 프로젝트를 구성하는 컨테이너들을 함께 관리
  - 여러 파일로 분리: 용도가 다른 설정이나 독립적으로 관리할 프로젝트를 구분

- Docker Compose YAML 내용 양식
```sh
services:                  # 실행할 컨테이너(서비스) 목록 — 필수!
  서비스이름:              # 예: db, web (직접 정하는 이름)
    image: 이미지:태그     # 사용할 이미지
    container_name: 이름   # 컨테이너 이름 (생략 시 자동 생성)
    environment:           # 환경 변수 (-e)
      KEY: value
    ports:                 # 포트 연결 (-p) — ""로 감싸기
      - "호스트:컨테이너"
    volumes:               # 볼륨 연결 (-v)
      - 볼륨이름:컨테이너경로

volumes:                   # 사용할 볼륨 선언 (최상위)
  볼륨이름:
   external: true          # compose 내부/외부 볼륨 지정
```

## 2️⃣ Docker compose 실제로 활용하기

### 1. 프로젝트 내 compose.yaml 파일 생성 및 작성
- pg-lab 프로젝트 폴더 내 compose.yaml 파일 생성, 아래 내용 작성
```sh
services:                           # 실행할 컨테이너(서비스) 목록 
  db:                               # 서비스 이름을 db로 지정
    image: postgres:18              # postgres:18 이미지를 사용
    container_name: kant-pg         # 컨테이너 이름은 kant-pg
    environment:                    # 환경 변수 (-e) : POSTGRES_PASSWORD
      POSTGRES_PASSWORD: admin1234
    ports:                          # 포트 연결 (-p)
      - "5432:5432"
    volumes:                        # 볼륨 pgdata, 컨테이너 경로 /var/이하
      - pgdata:/var/lib/postgresql

volumes:                    
  pgdata:                           # 사용할 볼륨 pgdata
    external: true
    # compose 안에서 pgdata 볼륨을 새로 생성하지 않고,
    # compose 밖에서 기존에 만들어둔 pgdata 볼륨을 사용하도록!
```

- Docker Compose YAML 작성 내용 검증하기
```sh
docker compose config
# 이하 내용 출력되면 ok
```

### 2. Docker compose로 컨테이너 실행/삭제(up/down)
- compose로 컨테이너 실행(up)
```sh
docker compose up -d
```

- 현재 프로젝트의 compose 컨테이너 목록 확인
```sh
docker compose ps 
```

- 실행한 컨테이너 데이터 확인 (내부로 들어가지 않고 터미널에서 바로 확인하기!)
  - 이전 명령: docker exec -it kant-pg psql -U postgres까지만 작성하고 내부 프롬프트로 들어가 조회
  - 이번에는 kant_shop이라는 database(d)에 접속, "SELECT * FROM product"라는 command(c)를 실행까지 한번에
```sh
docker exec -it kant-pg psql -U postgres -d kant_shop -c "SELECT * FROM product"
 id |     name      | price  | stock 
----+---------------+--------+-------
  1 | 무선 키보드   |  35000 |   120
  2 | 게이밍 마우스 |  28000 |    85
  3 | 27인치 모니터 | 259000 |    15
  4 | USB-C 허브    |  19900 |   200

```

- compose로 실행한 컨테이너 중지(stop) 및 중지+삭제(down)
```sh
docker compose down 
# compose로 실행한 프로젝트를 정상적으로 중지한 뒤 삭제하고
# compose가 만든 기본 네트워크도 함께 정리해 줌(docker rm와 다른점)
# docker rm -f로 컨테이너를 지워도 compose.yaml 파일은 그대로 남음
```
