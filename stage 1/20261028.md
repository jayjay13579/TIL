## 2️⃣ Gitignore : Git 관리에서 폴더, 파일 제외시키기

작업 내 .gitignore 폴더를 만들고 파일 내 확장자명, 폴더명(/) 등 명시하여 Git 관리 대상에서 제외시킬 수 있음  
요점은 Git이 untracked 파일로 인식하지 못하도록 하는 것 (즉, 제외된 파일은 U 상태도 X)

> ✨ 단, .gitignore 파일 자체는 git 관리할 수 있도록 add, commit 하기 ✨

**1. 확장자명 제외**

```sh
# .gitignore(.으로 시작하는 hidden file) 생성
$ touch .gitignore 

# Git 관리 제외 파일 등록
생성한 gitignore 파일 내에 *.dat, *.tmp 등 작성, 저장
(=.dat, tmp 확장자 파일은 git을 관리하지 않겠다는 것을 명시)

기존 temp.dat 등 .dat 확장자였던 파일이 옅은 회색 처리되rh untracked 상태 해제
```

**2. 폴더 전체(하위 파일 포함) 제외**

```sh
# Logs 폴더 생성 후 이동
$ cd Logs 

# Logs 폴더 내 daily.log 파일 생성
$ touch daily.log 

# Git 관리 제외 파일 등록
.gitignore 파일 내 확장명에 [Ll]ogs 한 줄 추가
# []브라켓으로 대소문자 L시작하는 폴더, 파일 모두 무시할 수 있도록 작성
# (참고 : 리눅스에서는 폴더도 파일로 인식)
# .gitignore 에서는 주석을 별도 줄에 작성해야 인식함
```

📌 **[참고] 로컬, 원격 repo의 커밋 수준 차이 확인**

## 4️⃣ Git reset : 다른 버전의 상태로 이동

```
checkout vs git reset  

1. checkout : 내가 보고 있는 위치만 B로 이동, main은 여전히 C에 있음
   다시 main으로 돌아가면 C가 그대로 있음

A ── B ── C   ← main, 현재 위치
git checkout B
A ── B ── C   ← main
     ↑
  현재 위치

2. git reset : main을 B로 이동

A ── B ── C   ← main, 현재 위치
git reset --hard B
A ── B   ← main, 현재 위치

     C   (main에서는 더 이상 가리키지 않음)


# checkout: 책갈피는 그대로 두고, 내가 다른 페이지를 펼침
# reset: 책갈피를 다른 페이지로 옮김

```

- Git reset --soft/mixed/hard 커밋 해시값
  - soft : staging area 상태 유지, 커밋 직전 단계로 이동.    
    repo에서 커밋만 지운 상태
  - mixed(기본값) : working dr 상태 유지, staging area에는 올라가지 x, git add . 직전 단계로 이동
  - hard : working tree 상태까지 완전히 삭제, 작업 전으로 돌아감

  |구분|Working dir|Staging area|Repository|
  |---|---|---|---|
  |soft|o|o|x|
  |mixed|o|x|x|
  |hard|x|x|x|


### mixed option 코드 예시

```sh
# 기존 로그 확인
$ git log --oneline
008d704 (HEAD -> main) docs: add push command
655b30b docs: 내용 추가

$ git reset --mixed 300b264
Unstaged changes after reset:

# head 이동 상태 확인
$ git log --oneline

  (use "git add <file>..." to update what will be committed)

```

## 5️⃣ git reflog(reference log)로 reset 등 되돌리기

reflog : head가 어디로 움직였는지 기록한 이동 내역
  - 커밋할 때뿐 아니라 reset으로 이동한 것도 기록하기 때문에 reset을 되돌릴 수 있음

```sh
# reflog로 head log 확인(reset 직전에 head가 있었던 커밋 찾기)
$ git reflog 
300b264 (HEAD -> main, origin/main, origin/HEAD) HEAD@{0}: reset: moving to 300b264
008d704 HEAD@{1}: commit: docs: add push command
655b30b HEAD@{2}: commit: docs: 내용 추가
300b264 (HEAD -> main, origin/main, origin/HEAD) HEAD@{3}: commit: docs: 코드 수
정
5c65c5e HEAD@{4}: clone: from https://github.com/jayjay13579/kant-study.git

# 되돌릴 지점으로 이동(HEAD@{N}까지만 적기)
jihey@LAPTOP-T7TVDFIE UCRT64 C:/Users/jihey/kant-study (main)
$ git reset --hard HEAD@{1}

# git log에서 커밋 복구된 것 확인
$ git log --oneline
008d704 (HEAD -> main) docs: add push command # reset명령에 따라 로컬main 이동
655b30b docs: 내용 추가
300b264 (origin/main, origin/HEAD) docs: 코드 수정 # 마지막으로 push된 커밋 단계
5c65c5e feat: Llogs 제외 추가
e4e081e feat: .gitignore file 생성
2c542a5 docs: README.md 추가
```

## 1️⃣ git branch, checkout : 브랜치 만들고 head 이동하기

```sh

# git branch : 브랜치 목록 확인
$ git branch
  feature/login
```

## 2️⃣ git merge : main 브랜치로 병합하기

- fastforwarding 방식
- feature를 main으로 합치는 경우 -> 내 작업위치는 main이어야 함!!

```sh
jihey@LAPTOP-T7TVDFIE UCRT64 C:/Users/jihey/kant-study (main)
```

## 3️⃣ git branch --delete : main 병합 후 branch 삭제하기

```sh
# main으로 이동
$ git checkout main
Switched to branch 'main'
Your branch is up to date with 'origin/main'.

# 브랜치 삭제(단, 커밋 등 모두 완료된 상태여야 함)
$ git branch --delete feature/login

# 브랜치 목록에서 삭제된 것 확인(main만 남음)
$ git branch --list
* main
```

혹은 한 줄로도 명령어 작성 가능

```sh
# 병합 후 삭제
$ git branch -D feature/login
```

> main과 타 브랜치의 진행 단계가 차이가 날 때는 merge commit이 생김
