## 2️⃣ 데이터 변경 조회(RETURNING) / 변경(UPDATE)

### 1. RETURNING : 변경 행만 바로 확인하기(psql만의 문법)
- RETURNING은 INSERT, UPDATE, DELETE 등 명령으로 변경된 행의 값을 바로 반환,
  SELECT * FROM 따로 실행 안해도 **변경된 행만 바로 결과 확인**할 수 있음 
- RETURNING *; 혹은 RETURNING 컬럼명; 과 같이 사용, 테이블명 따로 적지 X  
  같은 명령문 앞부분에 이미 적어둔 테이블을 기준으로 데이터 반환

```sql
INSERT INTO sports (sport_name) 
VALUES ('필라테스')
RETURNING *; -- insert into 대상인 sports 테이블 데이터 반환

-- 앞의 insert into 명령으로 변경(추가)된 한 행, 필라테스 행을 보여줌
5 필라테스
```

#### (4) DELETE + EXISTS
- EXISTS / NOT EXISTS (서브쿼리) : 서브쿼리의 결과 행 유무, 즉, 서브쿼리에  
  해당하는 자료의 존재 유무 확인
  - `EXISTS`: 서브쿼리의 결과 행이 하나라도 **있으면 참**
  - `NOT EXISTS`: 서브쿼리의 결과 행이 하나도 **없으면 참**

- EXISTS 다음의 서브쿼리에서는 '열의 값은 필요 없고, 행 존재 유무만 확인한다'는  
  의도를 보여주기 위해, 관례적으로 숫자 1을 SELECT 뒤 컬럼 자리에 넣음
```sql
EXISTS (SELECT 1 FROM enrollments e WHERE e.member_id = m.member_id)
```

`EXISTS`는 **결과 행이 있는지** 확인하므로 `SELECT` 뒤에 어떤 값을 적었는지는 중요하지 않다.
여기서 `1`은 회원 번호가 아니다. 존재 여부를 확인할 때 관례적으로 사용하는 값이다.
이 예시에서는 `SELECT *`를 써도 존재 여부의 결과가 같다.

- [예제] 회원가입 후 한번도 수강하지 않은 회원의 정보를 삭제  
  - SQL 친화적인 말로 바꾸면, '수강신청 테이블에 이 멤버 아이디가      
    하나도 없는 경우, 그 멤버의 행을 삭제한다'

```sql
-- 삭제 전 해당 정보 확인하기
SELECT m.member_id, m.name, m.join_date
FROM members m
WHERE NOT EXISTS (SELECT 1 FROM enrollments e WHERE e.member_id = m.member_id);
-- 이거 조인 안해도 이렇게 연결되는 경우 뭐임? 조인해야지만 다른 테이블 값
-- 쓸 수 있는 건줄 알았는데 여긴 조인 없잖아.
-- 서브쿼리(회원 테이블의 의 결과 행이 **하나도 없는 회원**을 남긴다.
-- 따라서 신청 내역이 없는 회원만 조회된다.

-- 고른 행 삭제하기
DELETE FROM members m
WHERE NOT EXISTS (SELECT 1 FROM enrollments e WHERE e.member_id = m.member_id)
RETURNING m.member_id, m.name;
```
