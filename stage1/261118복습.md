### 1. SQL문 작성 순서

<작성 순서>
SELECT      -- 무엇을 보여줄지
FROM        -- 어디서 가져올지
JOIN ... ON -- 어떤 테이블을 어떻게 연결할지
WHERE       -- 연결한 결과에서 어떤 행을 남길지
GROUP BY    -- 남은 행을 무엇을 기준으로 묶을지
HAVING      -- 어떤 그룹을 남길지
ORDER BY    -- 결과를 어떤 순서로 보여줄지

=> 작성은 출력, 출처, 연결 후 조건!, 그룹, 그룹 조건, 정렬
JOIN 이후에 WHERE로 조건 주기 잊지 말자!
순서 틀리면 syntax error 발생

<실행순서>
FROM / JOIN으로 데이터 연결
WHERE으로 개별 행 거르기
GROUP BY로 묶기
SELECT 각 그룹별 출력(COUNT도 그룹별로)
ORDER BY로 정렬

=> 실제 실행에서는 먼저 연결하고, 거르고, 묶고, 센다(COUNT)!

** COUNT + GROUP BY 쓸 때 항상 헷갈렸던 부분임...
왜냐하면 SQL문만 순서대로 봤을땐 COUNT가 그룹별로 세주는게 와닿지 않음
뭔가 COUNT를 컬럼쪽에 먼저 쓰니까 전체 행을 세줄것 같은 느끼임
근데 일단 GROUP BY를 아래 적는 순간 바로 그룹별 COUNT가 적용된다는 것
GROUP BY가 있으면 COUNT가 각 그룹 안에서 따로 작동함

### 2. JOIN 을 여러번 하는 경우 논리를 어떻게 따라갈까?

강사 instructors
| instructor_id | name |
|---:|---|
| 1 | 지혜 |
| 2 | 민수 |
| 3 | 영희 |

강좌 courses
| course_id | instructor_id | sport_id |
|---:|---:|---:|
| 101 | 1 | 10 |
| 102 | 1 | 10 |
| 201 | 2 | 20 |

신청 enrollments
| course_id | enroll_month |
|---:|---|
| 101 | 2026-11 |
| 101 | 2026-11 |
| 201 | 2026-10 |

종목 sports
| sport_id | sport_name |
|---:|---|
| 10 | 수영 |
| 20 | 골프 |


#### (1) 첫번째 join : 강사 + 강좌
- 강사당 그 사람이 담당하는 강좌들이 행별로 나옴
- 한 강사가 강좌 여러개를 담당하면, 강사 정보가 강좌마다 반복되어 모두 출력

FROM instructors i
LEFT JOIN courses c
    ON i.instructor_id = c.instructor_id

| 강사 | course_id | sport_id |
|---|---:|---:|
| 지혜 | 101 | 10 |
| 지혜 | 102 | 10 |
| 민수 | 201 | 20 |
| 영희 | NULL | NULL |
--> 강좌(왼쪽) 기준으로 조인했으므로, 우측 데이터 없어도 NULL로 채워져서 나옴

#### (2) 두 번째 JOIN: 여기에 11월 신청 연결
- 첫번째 조인 결과(강사+강좌)에 신청 내역을 연결하되, 강좌 번호 기준으로 짝을 찾음
- 첫번째 조인 결과 자체가 다음 조인의 왼쪽 테이블 역할 수행

LEFT JOIN enrollments e
    ON c.course_id = e.course_id
    -- 첫번째 조인결과에 들어있는 강좌 번호와 신청 테이블의 강좌번호 비교
    -- ON 뒤에는 두 테이블의 행을 어떤 조건으로 연결할지 적음(AND로 조건 두 개를 묶음)
    AND e.enroll_month = '2026-11'-- 꼭 key 연결 말고도 이런 조건도 적을 수 있음
    -- 강좌 번호가 같고, 신청 월이 11월인 정보만 표시해줘!
    -- 근데 LEFT JOINT이니까, 표시될 것 없어도 그 행 없애지말고 NULL로 살려 보여달라

** ON의 조건은 결과에서 행을 제거하는 조건이 아님!!!
** 두 행을 서로 붙일 수 있는지 판단하는 조건임!! 

| 강사 | 강좌 번호 `c.course_id` | 신청의 강좌 번호 `e.course_id` | 신청 월 |
|---|---:|---:|---|
| 지혜 | 101 | 101 | 2026-11 |
| 지혜 | 101 | 101 | 2026-11 |
| 지혜 | 102 | NULL | NULL |
| 민수 | 201 | NULL | NULL |
| 영희 | NULL | NULL | NULL |

강좌 101에는 11월 신청이 두 건이라 정보가 2건 

민수에게는 10월 신청이 있지만 ON의 11월 조건에 맞지 않아 짝이 없음, 매칭안됨
영희도 신청 월이 NULL이라서 매칭 안됨
그래도 LEFT JOIN(짝 못찾아도 왼쪽행은 보여줘)이므로 민수, 영희 강좌(NULL) 남고 신청 쪽 NULL이 됨
** 만약 여기서 INNER JOIN 이었다면 양쪽 모두의 조건이 맞는 짝들만 보여지므로 행 안나옴

#### (3) 세번째 조인 : 앞에 종목 이름 연결
- 두번째 조인 결과(강사+강좌+신청 강좌) 연결한 상태에 종목 이름 연결

LEFT JOIN sports s
    ON c.sport_id = s.sport_id

| 강사 | 강좌 번호 | 신청의 강좌 번호 | 종목 |
|---|---:|---:|---|
| 지혜 | 101 | 101 | 수영 |
| 지혜 | 101 | 101 | 수영 |
| 지혜 | 102 | NULL | 수영 |
| 민수 | 201 | NULL | 골프 |
| 영희 | NULL | NULL | NULL |

=> 이 상태를 GROUP BY로 묶고 COUNT하면 최종적으로:
| 강사명 | 종목 | 담당강좌수 | 이번달신청 |
|---|---|---:|---:|
| 지혜 | 수영 | 2 | 2 |
| 민수 | 골프 | 1 | 0 |
| 영희 | NULL | 0 | 0 |


**모든 강사**를 남기고 싶어서 instructors → courses에 LEFT JOIN
**신청이 없는 강좌**도 남기고 싶어서 courses → enrollments에 LEFT JOIN
**종목 정보가 연결되지 않아도** 앞의 행을 남기고 싶어서 sports에도 LEFT JOIN


FULL OUTER JOIN? 매칭되지 않은 행도 양쪽에서 모두 보여줌
강사 기준으로 나랩이를 세우고 싶은데 강사가 빈칸으로 나오는 경우도 생기고
11월 뿐 아니라 10월 등등 다른 월 것(짝을 못 찾은 자료들)도 양쪽에서 모두 보여줌





SELECT
    i.name AS 강사명,
    s.sport_name AS 종목,
    COUNT(DISTINCT c.course_id) AS 담당강좌수,  -- ← 실제 강좌를 중복 없이 세기
    COUNT(e.course_id) AS 이번달신청           -- ← 연결된 11월 신청 건수 세기
FROM instructors i
LEFT JOIN courses c
    ON i.instructor_id = c.instructor_id
LEFT JOIN enrollments e
    ON c.course_id = e.course_id
    AND e.enroll_month = '2026-11' -- 11월 등록을 짝으로..LEFT JOIN이므로 없으면 NULL
LEFT JOIN sports s
    ON c.sport_id = s.sport_id
GROUP BY i.name, s.sport_name  -- ← 같은 이름의 강사 구분
ORDER BY 이번달신청 DESC, 강사명;
