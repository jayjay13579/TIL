# 01 [DB] 데이터 조회/집계/결합, 서브쿼리

## 1️⃣ 데이터 조회 및 집계, GROUP BY와 HAVING

### 1. 조건 조회

#### (1) AND, OR로 조건 묶기
- 과목 아이디가 1이고(AND) 수강 시간이 9시 전이거나(0R) 초급 레벨
```SQL
SELECT course_name, level, start_time
FROM courses
WHERE sport_id = 1
AND (level = '초급' OR  start_time < '09:00');
```

#### (2) CASE WHEN/ELSE ~ THEN ~ END
- CASE 문 : 조회 결과를 출력하면서, 조건에 따라 만들어진 값을 하나의 추가 열로 보여줌
  - WHERE처럼 조건 맞춰 필터링을 해주는 것 X, 자료 다 보되 태그를 추가하는 느낌..! ⭐
  - 문법 : CASE WHEN 조건1 THEN 값1 / WHEN 조건2 THEN 값2 / ELSE 값3 / END (AS 별칭)

- 요금구분 열을 추가로 보여주며 60년생 혹은 그보다 나이가 많으면 '할인' 태그,  
  00년생 혹은 그보다 나이가 적은 경우 '청소년' 태그를 붙여 자료를 조회
```SQL
SELECT name, birth_year,
        CASE WHEN birth_year <= 1960 THEN '할인'    -- 60년대생 이하면 값이 '할인'
             WHEN birth_year >= 2000 THEN '청소년'  -- 00년대생 이상은 값이 '청소년'
             ELSE '일반'                            -- 나머지는 값이 '일반'
        END AS 요금구분  -- 마지막 END 잊지마! ⭐ 추가 열을 '요금구분'으로 명명
FROM members
ORDER BY birth_year, name;

-- 결과
  name  | birth_year | 요금구분 
--------+------------+----------
 신민재 |       1960 | 할인
 정유진 |       1960 | 할인
 신지아 |       1962 | 일반
 황은지 |       1962 | 일반
```

- [참고] CASE보단 VIEW?
  - CASE문을 자주 쓰면 쿼리 속도가 떨어지므로 남발은 지양, 대신 VIEW 활용

```SQL
-- VIEW 만들기
CREATE VIEW member_fare_view AS  -- ← 앞선 CASE문 쿼리에 뷰 이름 지정
SELECT
    name,
    birth_year,
    CASE
        WHEN birth_year <= 1960 THEN '할인'
        WHEN birth_year >= 2000 THEN '청소년'
        ELSE '일반'
    END AS 요금구분
FROM members;

-- VIEW 활용하기
SELECT *
FROM member_fare_view -- ← 앞의 쿼리문을 다 적지 않고도 활용 가능
ORDER BY birth_year, name;
```

#### (3) 정렬 : ORDER BY ~ ASC / DESC

- ORDER BY 컬럼 ASC / DESC : 컬럼 기준으로 오름 / 내림차순 정렬
```SQL
-- 8만원 이상 과정 중 수강료가 비싼 순서대로 정렬
SELECT course_name, fee
FROM courses
WHERE fee >= 80000
ORDER BY fee DESC, course_name;
```

- NULL은 가장 큰 값 : ASC 정렬시 NULL이 가장 나중에, DESC에선 NULL이 먼저!
```SQL
SELECT name, email
FROM members
ORDER BY email DESC, name;
-- 결과

--------+----------------------

 권우진 | 
 박서윤 | seoyun@example.com
 최민준 | minjun@example.com
```

### 2. 데이터 집계

#### (1) COUNT

- COUNT(*) : 모든 행을 집계
- COUNT(COLUMN) : 해당 컬럼 값이 NULL인 행은 빼고 집계
- COUNT(DISTINCT COLUMN) : 해당 컬럼 값 중복없이 집계 (중복있어도 하나로만 집계)

```SQL
SELECT
    COUNT(*)                AS 회원수       , -- 콤마 항상 잊지 않기!
    COUNT(email)            AS 이메일있음   , -- 맨 앞에 쓰거나 줄맞춤해서 적기도
    COUNT(phone)            AS 전화번호있음 ,
    COUNT(DISTINCT region)  AS 거주지 -- region 컬럼 값 중복없이 하나씩만 집계 
FROM members;

-- 결과
 회원수 | 이메일있음 | 전화번호있음 | 거주지 
--------+------------+--------------+--------
     60 |         45 |           57 |      5
```

#### (2) MIN, MAX, SUM, AVG (+ROUND)
- MIN, MAX, SUM, AVG (COLUMN) 으로 컬럼 값의 최솟값, 최댓값, 합계, 평균 확인 가능
- ROUND(값, 소수점 자릿수)를 통해 지정한 소수점 자릿수까지 반올림된 값을 볼 수 있음
```SQL
-- 최저 수강료, 최대 수강료, 전체 정원 수, 평균 수강료
SELECT
    COUNT(*)            AS 강좌수,
    MIN(fee)            AS 최저수강료,
    MAX(fee)            AS 최고수강료,
    SUM(capacity)       AS 전체정원,
    ROUND(AVG(fee),2)   AS 평균수강료
FROM courses;

-- 결과
 강좌수 | 최저수강료 | 최고수강료 | 전체정원 | 평균수강료 
--------+------------+------------+----------+------------
     14 |      40000 |     150000 |      266 |   81785.71

-- 11월 강좌 신청 건수, 전체 매출, 최고 매출
SELECT
    COUNT(*)        AS 신청건수 ,
    SUM(pay_amount) AS 매출 ,
    MAX(pay_amount) AS 최고매출
FROM enrollments
WHERE enroll_month = '2026-11';

-- 결과
 신청건수 |    매출    | 최고매출  
----------+------------+-----------
       56 | 4286500.00 | 150000.00
```

### 3. GROUP BY와 HAVING

#### (1) GROUP BY
- GROUP BY 컬럼명 : 지정한 컬럼의 값이 같은 행들을 하나의 그룹으로 묶음
  - 특히, SELECT에 일반 컬럼과 집계 함수를 함께 쓰면, 보통 그 일반 컬럼을 GROUP BY로 묶음
```SQL
SELECT
    enroll_month    AS 신청월   ,
    COUNT(*)        AS 신청건수 ,
    SUM(pay_amount) AS 매출
FROM enrollments
GROUP BY enroll_month
ORDER BY enroll_month;

-- 결과
 신청월  | 신청건수 |    매출    
---------+----------+------------
 2026-08 |       46 | 3123500.00
 2026-09 |       48 | 3117000.00
 2026-10 |       50 | 3376500.00
 2026-11 |       56 | 4286500.00
```

- [참고] SELECT 일반 컬럼 + 집계함수 쿼리를 GROUP BY 없이 쓰는 경우?
  - 여러 행을 하나로 집계한 결과에 일반 컬럼의 어떤 값을 표시해야 할지 몰라 오류가 발생
```SQL
-- 신청월별 신청건수
SELECT
    enroll_month    AS 신청월   , -- 일반 컬럼
    COUNT(*)        AS 신청건수 , -- 집계 함수
    SUM(pay_amount) AS 매출       -- 집계 함수
FROM enrollments

-- GROUP BY가 없어 다음과 같은 에러 발생
ERROR:  column "enrollments.enroll_month" must appear in the GROUP BY (생략)
LINE 2:     enroll_month    AS 신청월 
```

#### (2) HAVING
- HAVING 조건 : GROUP BY로 묶은 **그룹 중**에서 조건에 맞는 **그룹**만 남기는 구문

```SQL
-- 과정 아이디별 등록을 취소하지 않은 사람들 수(=신청 수), 단, 그 수가 18이상
SELECT
    course_id, COUNT(*) AS 누적신청
FROM enrollments
WHERE status <> '취소' -- status IN ('수강중','수료') 보다 효율적
GROUP BY course_id
HAVING COUNT(*) >= 18
ORDER BY 누적신청 DESC, course_id; -- 별칭(누적신청)으로 결과값 정렬 가능

-- 결과
 course_id | 누적신청 
-----------+----------
        13 |       23
         8 |       21
        11 |       18

-- 지역구별 거주 회원 수, 단, 그 수가 10명 이상
SELECT 
    region, COUNT(*) AS 해당거주지회원수
FROM members
GROUP BY region
HAVING COUNT(*) >=10
ORDER BY 해당거주지회원수 DESC;

-- 결과
  region  | 해당거주지회원수 
----------+------------------
 서대문구 |               22
 마포구   |               17
 은평구   |               10
```

## 2️⃣ 조회 결과 결합 : UNION, JOIN

### 1. UNION
- 여러 조회 결과를 위아래로 붙이기, 행이 늘어남!
- 다른 테이블뿐 아니라 같은 테이블을 조회한 결과끼리도 결합 가능
- 단, 각 SELECT별 return 되는 COLUMN의 개수가 일치해야 묶을 수 있음!

#### (1) UNION (중복 불가)

- 같은 테이블 자료의 결합
```SQL
-- 과정 아이디가 4이고 등록 일자가 9, 10, 11월인 경우 조회 결과 결합
SELECT member_id FROM enrollments
WHERE course_id = 4 AND enroll_month = '2026-09'
UNION
SELECT member_id FROM enrollments
WHERE course_id = 4 AND enroll_month = '2026-10'
UNION
SELECT member_id FROM enrollments
WHERE course_id = 4 AND enroll_month = '2026-11'
ORDER BY member_id;

-- 결과(중복 없음)
 member_id 
-----------
        10
        11
        18
        37
        46
```

#### (2) UNION ALL (중복 허용)

- 같은 테이블 자료의 결합
```sql
-- 과정 아이디가 4이고 등록 일자가 9, 10, 11월인 경우 조회 결과 결합
SELECT member_id FROM enrollments
WHERE course_id = 4 AND enroll_month = '2026-09'
UNION ALL
SELECT member_id FROM enrollments
WHERE course_id = 4 AND enroll_month = '2026-10'
UNION ALL
SELECT member_id FROM enrollments
WHERE course_id = 4 AND enroll_month = '2026-11'
ORDER BY member_id;

-- 결과(중복 허용)
 member_id 
-----------
        10
        10
        10
        11
        11
        11
        18
        18
        37
        37
        46
        46
        46
```

- 다른 테이블 자료의 결합
```SQL
-- 아이디가 4인 과정들의 강사들 + 영등포구에 사는 회원들
SELECT '강사' AS 구분, name, phone FROM instructors  -- 강사 테이블 조회 결과
WHERE sport_id = 4
UNION ALL -- 중복 허용
SELECT '회원' AS 구분, name, phone FROM members  -- 회원 테이블 조회 결과
WHERE region = '영등포구';

-- 결과 
 구분 |  name  |     phone     
------+--------+---------------
 강사 | 배수민 | 010-3101-2207
 강사 | 차예린 | 
 회원 | 홍혜원 | 010-4895-6934
 회원 | 정서현 | 010-2479-2442
 회원 | 오예린 | 010-8384-9593
 회원 | 장은지 | 010-7121-3363
```

### 2. JOIN 
- 조건에 맞는 행끼리 연결하여 옆으로 붙이기, 열이 늘어남!

#### (1) INNER JOIN : 양쪽에서 일치하는 행만
- 양쪽 테이블 모두에서 값이 일치하는 행, 즉, 짝이 맞는 경우만 결합
  - [참고] Postgres에서 JOIN만 쓰면 자동으로 INNER JOIN으로 인식함!

**(ex) 과정목록 테이블에 강사 이름 붙이기 (연결은 강사 id로)**
```sql
-- INNER JOIN하여 과정, 강사 모두 매칭되는 행만 나옴, 빈칸 없음
SELECT c.course_id,
       c.course_name,
       i.name AS 강사
FROM courses c
JOIN instructors i ON c.instructor_id = i.instructor_id -- 연결고리 : 강사 id
ORDER BY c.course_id;

-- 결과
 course_id |   course_name    |  강사  
-----------+------------------+--------
         1 | 수영 초급 새벽반 | 한지수
         3 | 수영 중급 저녁반 | 오민재
         4 | 수영 상급 저녁반 | 오민재
```

#### (2) LEFT JOIN : 왼쪽 테이블은 모두
- 기준(왼쪽) 테이블 행을 모두 보여주고, 오른쪽 테이블 값 매칭되지 않으면 NULL 처리
```sql
-- LEFT JOIN하여 과정 기준 모든 행 보여주고 매칭된 강사없으면 NULL값
SELECT c.course_id,
       c.course_name,
       i.name AS 강사
FROM courses c
LEFT JOIN instructors i ON c.instructor_id = i.instructor_id
ORDER BY c.course_id;

-- 결과 : 강사가 매치되지 않아도 과정(기준, 왼쪽)은 모두 포함
 course_id |   course_name    |  강사  
-----------+------------------+--------
         1 | 수영 초급 새벽반 | 한지수
         2 | 헬스 자유이용    | 
         3 | 수영 중급 저녁반 | 오민재
```

#### (3) RIGHT JOIN : 오른쪽 테이블은 모두
- 조인되는(오른쪽) 테이블 행을 모두 보여주고, 기준(왼쪽) 테이블 값 매칭되지 않으면 NULL 처리
```sql
-- RIGHT JOIN하여 강사 기준 모든 행 보여주고 매칭된 과정없으면 NULL값
SELECT c.course_id,
       c.course_name,
       i.name AS 강사
FROM courses c
RIGHT JOIN instructors i ON c.instructor_id = i.instructor_id
ORDER BY c.course_id;

-- 결과 : 과정이 매치되지 않아도 강사(오른쪽)는 모두 포함
 course_id |   course_name    |  강사  
-----------+------------------+--------
        13 | 실버 스포츠댄스  | 배수민
        14 | 수영 마스터즈반  | 한지수
           |                  | 차예린
```

#### (4) FULL OUTER JOIN : 양쪽 모두
- 양쪽 테이블 전체 행을 포함
```sql
-- FULL OUTER JOIN하여 양쪽 테이블 모든 행 보여주고 각각 매칭되지 않은 값은 NULL값
SELECT c.course_id,
       c.course_name,
       i.name AS 강사
FROM courses c
FULL OUTER JOIN instructors i ON c.instructor_id = i.instructor_id
ORDER BY c.course_id;

-- 결과 : 매칭되지 않은 양쪽 행들 모두 포함
 course_id |    course_name     |  강사  
-----------+--------------------+--------
        10 | 골프 타석 자유이용 | 
        11 | 라틴댄스 초급      | 배수민
        14 | 수영 마스터즈반    | 한지수
           |                    | 차예린
```

## 4️⃣ 서브쿼리
- 하나의 SQL 쿼리 안에 들어가는 또 다른 쿼리
- scala sub query, inline view 등 종류가 있음

### 1. Scala Sub Query
- 서브쿼리 결과가 하나의 값으로 사용되는 경우

- 가장 기본적인 scala sub query, 조건에 서브쿼리 추가하는 경우
```sql
-- 수강료가 평균 수강료(sub query) 이상인 자료 확인
-- 평균 수강료 구한 값을 직접 적지 않고 서브 쿼리 활용

-- 서브 쿼리 : 평균 수강료
SELECT AVG(fee) FROM courses;

-- 쿼리(+서브 쿼리)
SELECT course_name, fee
FROM courses
WHERE fee > (SELECT AVG(fee) FROM courses) -- WHERE 조건에 서브쿼리 포함
ORDER BY fee DESC, course_name;

-- 결과
    course_name     |  fee   
--------------------+--------
 헬스 PT 그룹반     | 150000
 골프 중급반        | 130000
 골프 입문반        | 120000
 수영 마스터즈반    |  90000
 골프 타석 자유이용 |  90000
```

- 조회 COLUMN으로 scala sub query를 추가하는 경우
```sql
SELECT
    course_name,
    fee,
    ROUND((SELECT AVG(fee) FROM courses),2) AS 전체평균, --평균 수강료(소수2자리까지)
    fee - ROUND((SELECT AVG(fee) FROM courses),2) AS 평균과차이 -- 수강료 편차(수강료 - 평균)
FROM courses;

-- 결과
    course_name     |  fee   | 전체평균 | 평균과차이 
--------------------+--------+----------+------------
 수영 초급 새벽반   |  70000 | 81785.71 |  -11785.71
 헬스 자유이용      |  50000 | 81785.71 |  -31785.71
 수영 중급 저녁반   |  75000 | 81785.71 |   -6785.71
```

### 2. INLINE VIEW (FROM sub query)
- FROM 뒤에 넣은 서브쿼리, 서브쿼리 조회 결과를 하나의 임시 테이블처럼 바깥 쿼리에서 사용
- FROM (서브쿼리) AS 별칭 : 서브쿼리 조회 결과도 AS로 별칭을 줄 수 있음! 이 별칭은 테이블명처럼 사용 가능

#### (1) 서브쿼리만 작성해서 결과 잘 보이는지 확인
```SQL
SELECT member_id, SUM(pay_amount) AS total_paid
FROM enrollments 
GROUP BY member_id;
```

#### (2) 쿼리에 서브쿼리 넣어서 확인해보기
- SELECT *로 조회, 결과는 앞선 서브쿼리 조회 결과와 동일
```SQL
SELECT * 
FROM
(
    SELECT member_id, SUM(pay_amount) AS total_paid
    FROM enrollments 
    GROUP BY member_id 
) AS paid;  -- 서브쿼리 조회 결과에 별칭 부여
```

#### (3) 구체화해서 마무리하기
```SQL
SELECT member_id, total_paid
FROM
(
    SELECT member_id, SUM(pay_amount) AS total_paid
    FROM enrollments 
    GROUP BY member_id 
) AS paid 
WHERE total_paid >= 400000
ORDER BY total_paid DESC, member_id;
```
